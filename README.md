## 这是什么

一个**纯 PowerShell 单文件工具**（外加一个双击入口），用来把 OpenAI **Codex Desktop / ChatGPT 桌面版** 的界面语言设成简体中文。

它**不是**汉化补丁。它不开刀、不替换任何应用文件，只是打开应用**官方自己提供的**语言配置开关 `localeOverride`，指向应用**官方已经装好的**中文资源。

> 但光有它还不够 —— 应用还有一个**远程开关**决定「要不要加载语言包」。
> 这是 v1.2.0 开始查、v2.0.0 才彻底定案的事，也正是**你换几台电脑都汉化不了的根本原因**。见下一节。

所以：

| 你关心的 | 结果 |
|---|---|
| 需要联网下载语言包吗 | **不需要**，64 种语言、两套资源全部内置于应用包 |
| 需要联网吗 | **通常需要**：应用默认要从 `ab.chatgpt.com` 取远程开关 `enable_i18n`（该域名国内被墙）；但 **v2.1.0 新增「离线开关注入」，无代理/离线环境也能直接汉化**（见下） |
| 需要装 Node.js / Python 吗 | **不需要**，只用 Windows 自带的 PowerShell 5.1 |
| 需要管理员权限吗 | **不需要**，只写你自己的用户目录 |
| 应用商店更新后失效吗 | **不失效**，配置与缓存键都现场算、当场重写 |
| 会被判定为应用被篡改吗 | **不会**，`WindowsApps` 目录一个字节都不碰 |
| 会碰应用的本地存储吗 | **v2.1.0 起会**：`离线开关注入` 会向应用本地缓存的 LevelDB 写入一条开关（自动备份、可还原），见「离线开关注入」一节 |

## 界面变中文的两个条件

这是本项目反复取证后**唯一站得住的结论**。界面要显示中文，必须两个条件**同时**成立：

| | 条件 | 由谁决定 | 能否离线完成 |
|---|---|---|---|
| **条件一** | `config.toml` 里 `[desktop] localeOverride = "zh-CN"` | 本工具 | ✅ 纯本地，本工具负责 |
| **条件二** | 应用远程开关 `enable_i18n = true` | OpenAI 的 Statsig 配置服务 | ✅ **三选一**：联网拉取一次；走系统代理；或 **v2.1.0 直接离线注入开关缓存** |

### 关键事实：语言包是内置的，开关才是卡点

把应用包 `app.asar`（309.9 MB / 9,044 个文件）的目录树逐项解开核对（v2.0.0 实测）：

| 资源 | 位置 | 实测数量 |
|---|---|---|
| 原生菜单文案 | `native-menu-locales/<locale>.json` | **64 种**，`zh-CN.json` = 11,884 字节 / **196 键** |
| 前端语言包 | `webview/assets/<locale>-<hash>.js` | **64 种**，`zh-CN-cd93ae89e5cf.js` = 1,394,280 字节（面板显示 1.3 MB） |

两套语言列表**一一对应**（64 = 64，无落单），包含 `zh-CN` / `zh-TW` / `zh-HK` / `ja-JP` / `ko-KR` 等。
前端语言 chunk 是**本地相对路径动态 `import()`** 加载的：

```js
// webview 里的实际逻辑（简化）
const layer = statsig.getLayer('72216192');
const on    = layer?.get('enable_i18n', false);   // ← 拿不到就是 false
if (on) { await import(`./zh-CN-cd93ae89e5cf.js`); }  // 只有为真才真正换语言
```

也就是说：**中文包明明躺在硬盘里，但"要不要用它"由一个远程开关决定。**

### 条件二为什么会失败

应用启动时向这个地址拉取配置：

```
POST https://ab.chatgpt.com/v1/initialize
```

我们**用同一套请求实测过**（不是猜测）：

| 事实 | 证据 |
|---|---|
| `enable_i18n` 在服务端是 **`rule_id: "default"`** | 拉回 160 个 layer，`layer_configs.72216192.value = {"enable_i18n": true, "locale_source": "IDE"}` |
| 也就是说**与账号、设备、抽签百分比全都无关** | `rule_id` 是 `default` 而不是某个实验分组 |
| `ab.chatgpt.com` 在国内**直连必超时** | 本机实测：DNS 被污染 + TCP 443 超时 |
| 但同厂商的 `api.oaistatsig.com`（只做事件上报）**直连正常** | 所以应用"看着能上网"，开关却永远拿不到 |

**结论：应用只要能成功访问 `ab.chatgpt.com` 一次，界面就会变中文；结果落盘缓存后长期有效，之后断网也还是中文。**

而应用的网络栈是 Electron，**走的是 Windows 系统代理（WinINET）** —— 这就是为什么"开了代理就好了"，
也是为什么**代理没覆盖这个域名时依然无效**（很多订阅规则只写 `chatgpt.com`，漏掉 `ab.chatgpt.com`）。

### 三个怪现象，一次说清

| 现象 | 真正原因 |
|---|---|
| **「菜单栏展开是中文，界面却全是英文」** | 原生菜单跟随**系统语言**（与 `enable_i18n` 无关）；界面文字才受开关控制。两套机制，所以会分裂 |
| **「设置里明明有中文选项，选了没反应」** | 同一个 layer 被读了两次、**默认值不同**：语言选择器那边是 `.get('enable_i18n', true)`（默认显示中文选项），真正加载语言包那边是 `.get('enable_i18n', false)`（默认不加载） |
| **「在自己机器上导出开关，导入新电脑没用」** | 见下一节 —— 缓存键绑登录身份 + 额外校验，**跨机器必然失配** |

## 为什么"盲搬缓存"走不通，但"算出键再注入"能行

v1.2.0 曾经提供 `[7] 汉化加速包`（把本机内存好的 Statsig 缓存导出、再导入另一台电脑），**3 台新机器实测全部无效**，v2.0.0 删除。

从表面看，应用把开关结果存在本地，键是明文可读的 `statsig.cached.evaluations.<hash>` —— 那直接"整目录搬过去"不就行了吗？**不行**，原因在 `<hash>` 和值本身都绑定了机器：

| 障碍 | 后果 |
|---|---|
| `<hash>` 由登录身份算出 | **来源机器**登录的账号 / 设备标识不同 → 搬过去的键名在目标机器上根本对不上 |
| 取值时应用还校验 `stableID` 必须与本机一致 | 设备标识不同 → 缓存被视为**无效**，直接丢弃重取 |

所以"**把别台机器的缓存照搬过来**"这整条路是死路 —— 问题永远出在"搬来的键绑的是来源机器的标识"。

**但这不等于"机制上不可能"**。v2.1.0 换个思路：不搬键，而是在**目标机器上现场算键、当场写入**。因为这种缓存键的输入其实只有本机 `stableID` 这一个变量，而 `stableID` 就存在应用自己的缓存里（`statsig.stable_id.685440364`，这个键名跨机器常量），新机器随时能读到 —— 见下一节「离线开关注入」。

## 离线开关注入（v2.1.0 · 无代理 / 离线专用）

针对"国内无代理、甚至离线的机器根本连不上 `ab.chatgpt.com`"这最后一道坎，v2.1.0 给出收官解法：
**不联网、不代理，直接把汉化开关写进应用本地的 LevelDB 缓存**。相当于"替应用凭空造出一次联网结果"——服务端明明恒为 `true`，那就直接把 `true` 落进应用读取的缓存里。语言包 64 种本来就在应用里，开关拿到了，界面自然就是中文。

### 原理

1. 读目标应用自己的 `stableID`（存于 `statsig.stable_id.685440364`，键名跨机器常量）
2. 按 DJB2 公式现场算出这台机器专属的评估缓存键 `statsig.cached.evaluations.<hash>`
3. 按 LevelDB 的 log 格式（WriteBatch + CRC-32C）把开关 payload 追加写进应用缓存的 `.log`
4. 完全退出应用再启动 → 界面变中文

> **金标准数字**：stableID 键后缀 = `685440364`；本机 evaluations 键后缀 = `2607623780`。
> 面板/日志里这两个数，尤其 `2607623780`，一旦变了就说明哈希公式又错了（应用实现是 `DJB2`：初值 0、每次 `t=(t<<5)-t+charCode`，即 **31×t**，不是经典 DJB2 的 33×t）。

### 用法（全程无需代理）

1. **完全退出** Codex / ChatGPT（托盘图标右键 → 退出，**不是**只点窗口关闭）
2. 双击 `Codex一键汉化.cmd` → 菜单 `[7] 远程开关自检与修复` → `2) 离线开关注入`
   或命令行：`-Action inject`
3. 面板应显示：备份成功、使用的 stableID、缓存键 `statsig.cached.evaluations.2607623780`、写入 + 自检通过
4. 重新打开应用 → 界面为中文

### 备份与还原

注入前工具会**先把应用缓存目录整体备份**到 `backups\leveldb.<时间戳>\`（备份失败就中止，绝不动真机）。想还原：把 `backups\` 里对应目录改回原名覆盖即可；或按 `[4]` 还原英文设置。

### ⚠️ 火绒 / 杀软误报

`离线开关注入` 会**直接构造二进制写入应用缓存的 `.log` 文件**，行为特征和"加密文件落盘"的勒索病毒很像，
**火绒这类杀软极可能把它当病毒隔离**（实测多次复现「写入成功但文件随即消失」）。
遇到这类现象，先把项目目录 / 临时目录加进火绒**信任区**（或从隔离区恢复），再重试。这不是脚本 bug。

## 为什么不需要第三方汉化包

GitHub 上流传的第三方汉化包（例如 `codex-zh-CN-v0.1.2` / `v5.5.5`）走的是
**「把 `app.asar` 复制到用户目录 → 二进制打补丁 → 顶替原文件」** 这条路。
在新版应用上，这条路不但没必要，而且是**负优化**：

| 对比项 | 第三方汉化包 | 本项目 |
|---|---|---|
| 原理 | 复制 1.8 GB 应用到 `~/.codex/zh-cn-patched`，改写 `app.asar` | 只写官方支持的配置项 `localeOverride` |
| 依赖 | 必须装 Node.js | 只用系统自带 PowerShell |
| 额外磁盘占用 | **+1.8 GB 副本 + 310 MB 备份** | **0** |
| 商店更新后 | 必然失效，要重新打补丁 | **依然有效** |
| 中文完整度 | 原生菜单 **73 键**（缺 128 键） | 应用自带 **196 键**，一字不缺 |
| 需要 VPN / 联网 | 要从 GitHub 下载 | 语言包不用下载；但首次要让应用访问 `ab.chatgpt.com` 取一次开关 |
| 风险 | 修改应用文件，可能触发完整性校验 | 应用文件**一个字节都不动** |

**为什么第三方包反而更差**：新版 `app.asar` 里**本来就内置了 64 种语言**，其中
`native-menu-locales/zh-CN.json` 有 **196 个词条**，还带一个 **1.3 MB 的官方前端中文包**
（`webview/assets/zh-CN-*.js`）。而第三方包塞进去的那份只有 73 键 —— **它会把你原本完整的中文
覆盖成残缺版**（关于对话框、更新确认、浏览器面板菜单等 128 条直接变成英文）。

## 它到底改了什么

**只动你自己用户目录下的 3 个文件 + 1 个目录；应用安装目录与应用本地存储全程只读、从不写入。**

| 文件 | 改动 |
|---|---|
| `%USERPROFILE%\.codex\config.toml` | 在 `[desktop]` 段写入 `localeOverride = "zh-CN"`（改前自动备份） |
| `%USERPROFILE%\.codex\computer-use\config.json` | 同步 `locale` 与两条覆盖层文案（见下，尽力而为） |
| `%USERPROFILE%\.wakecat-i18n.json` | 本工具自己的配置（首次运行后生成） |
| `Codex一键汉化\backups\` | 上面文件的带时间戳备份，每个文件只留**最近 5 份** |
| `Codex一键汉化\诊断报告-<时间戳>.txt` | 仅在你于 `[7]` 里选「保存诊断报告」时生成（不含账号/密钥） |

- 若 `%USERPROFILE%\.codex` 不存在（应用装完还没启动过），工具会**自动创建**。
- 若脚本所在目录不可写，备份会自动改到 `%LOCALAPPDATA%\Codex-i18n\backups`，绝不影响汉化本身。
- **`C:\Program Files\WindowsApps\...` 与你自己的应用 Local Storage 都只读，从不写入。**

### 关于那两条覆盖层文案

应用内置的 `zh-CN.json` 里**没有** `computerUseOverlay.usingComputer` / `escToCancel` 两个键
（我们把 196 个键逐个展开核对过），所以「ChatGPT 正在使用你的电脑」浮层会回退成英文。
工具会尝试把它们补进 `computer-use/config.json`：

```json
"usingComputer": "ChatGPT 正在使用你的电脑",
"escToCancel":   "按 Esc 取消"
```

> ⚠️ **诚实提醒**：`computer-use/config.json` 是**应用自己托管**的文件。实测它会在应用启动时被重写 ——
> `strings` 恢复成内置英文默认值，并补上 `accentColor` / `direction` 字段（只有 `locale` 被保留）。
> 所以这一步是**尽力而为**，不保证长期生效。如果覆盖层仍显示英文，那是**应用自身没有翻译这两条文案**，
> 与本工具无关，也**不影响界面主体语言**（菜单、设置、对话框由官方 196 键 + 1.3 MB 前端包决定）。

## 工作原理

### 1. 官方开关 `localeOverride`（条件一）

Electron 应用的界面语言由 `~/.codex/config.toml` 里的这一段决定：

```toml
[desktop]
localeOverride = "zh-CN"
```

工具做的就是**幂等地**维护这一行：`[desktop]` 段存在就改键，不存在就建段，要还原就删键。
所以它改的是一个**用户配置文件**，应用商店更新应用包时不会受影响。

### 2. 远程开关 `enable_i18n`（条件二，真正的卡点）

应用启动时向 `https://ab.chatgpt.com/v1/initialize` 拉取 Statsig 动态配置，
其中 Layer `72216192` 里的 `enable_i18n` 决定要不要加载语言包：

```js
// 加载语言包的那段代码 —— 默认值 false
Aon('72216192').get('enable_i18n', false) && loadLocaleMessages(locale)

// 语言选择器的那段代码 —— 默认值 true（所以能"看到"中文选项）
Zt('72216192').get('enable_i18n', true)
```

两处默认值不一致，就制造了「**能选中文、选了没用**」的假象。
实测服务端该值为**无条件的 `true`**（`rule_id = default`），所以问题从来不在于"给不给"，
而在于"**拿不拿得到**"。

| 域名 | 作用 | 国内直连 |
|---|---|---|
| `ab.chatgpt.com` | **下发** `enable_i18n` 等开关 | ❌ DNS 污染 + TCP 超时 |
| `api.oaistatsig.com` | 事件上报 | ✅ 正常 |

### 3. 本工具的判定方式：实测，而不是"看缓存有没有"

`[7]` 会**照抄应用的那次请求**（同一个 URL、同一个客户端 key、同样的 body 形状）去拉一次，
直接把 `enable_i18n` 的真实取值读回来给你看：

| 实测结果 | 含义 |
|---|---|
| `通过 系统代理 http://127.0.0.1:7890 取到开关：enable_i18n = true` | ✅ 应用下次启动就能拿到中文界面 |
| `拉取失败（直连）` | ❌ 应用也拿不到 → 必须开系统代理 / TUN |
| `请求成功，但 enable_i18n = false` | ⚠️ 极少见，说明服务端行为变了，请把诊断报告发回来 |

探测时会同时测**系统代理（应用实际走的路）**与**直连**两条路径，并把两条都打印出来。
另外它还会读一遍你本机的 localStorage 快照作为**软信号**（只读，仅用于参考）。

### 4. 应用定位是四级降级

不匹配版本号，以下四步依次尝试，命中即用：

1. `[9] 设置` 里手动指定的 `appPath`
2. 正在运行的进程（`ChatGPT.exe` / `Codex.exe`）反推安装目录
3. `Get-AppxPackage` 模糊匹配 `OpenAI.*` / `*Codex*` / `*ChatGPT*`
4. 常见目录扫描（`%LOCALAPPDATA%\Programs`、`C:\Program Files\Codex`、桌面、下载目录…）

所以 MSIX 商店版、便携版都能认，换新版本也不怕。

### 5. 副产物清理

第三方汉化包会在用户目录留下这些可再生副本，`[6]` 会列出占用并送进**回收站**：

| 路径 | 典型大小 |
|---|---|
| `%USERPROFILE%\.codex\zh-cn-patched` | ~1.8 GB |
| `%USERPROFILE%\.codex\zh-cn-install-backups` | ~310 MB |
| `%USERPROFILE%\.codex\.zh-cn-backups` | 极小 |
| `%USERPROFILE%\.codex\codex-desktop-path.txt` | 极小 |

## 换台电脑能用吗

**脚本本身完全可移植；而"界面是否真的变中文"，现在有三条路，任何一条满足即可：让应用访问到 `ab.chatgpt.com`，走系统代理，或直接 `[7]→2 离线开关注入`（最后一条**完全不依赖外网**）。**

| 依赖项 | 情况 |
|---|---|
| 本机用户名 / 盘符 / 应用版本号 | **未写死**，路径全部来自 `%USERPROFILE%` / `%LOCALAPPDATA%` / `$PSScriptRoot` |
| 应用版本 | 不校验版本号，靠四级降级**自动定位**任意 26.9xx+ 版本 |
| Node.js / Python / 第三方库 | **不需要**（脚本只用 PowerShell 5.1 内置能力） |
| 管理员权限 | **不需要** |
| 中文字体 | **不需要**（横幅用半角块字符） |
| 操作系统 | Windows 10 / 11（需自带 PowerShell 5.1） |
| **外网** | **离线也能汉化**：`[7]→2 离线开关注入` 直接写开关缓存，不需要 `ab.chatgpt.com` 可达 |

### 换机器的正确姿势

```
[1] 一键汉化
      ↓
二选一：
  ① 联网/代理型：确认系统代理或 TUN 已开启（并在 [8] 里确认 ab.chatgpt.com 可达）
      → [7] 远程开关自检与修复 → 看到 "取到开关：enable_i18n = true" 才算过
  ② 无代理/离线型（推荐给国内新机器）：直接 [7] → 2) 离线开关注入
      ↓
完全退出应用（托盘右键退出）→ 重新打开  →  界面变中文
      ↓
之后可以不联网：开关已缓存进应用本地，长期有效
```

> ① 需要外网一次；② **全程离线**，适合国内无代理/离线的机器 —— 这正是 v2.1.0 新增、用来绕开"连不上 `ab.chatgpt.com`"的收官方案。

### 需要留意的地方

- **代理规则要覆盖 `ab.chatgpt.com`**。不少订阅只写 `chatgpt.com` 或按 IP 分流，会漏掉这个子域。
  用 `[8] 网络 / 代理检测` 看它的"代理"那一列是否可达，最直观。
- **只开浏览器代理没用**。应用走的是**系统代理（WinINET）**；纯浏览器插件式代理不改变系统代理设置。
  开 TUN / 系统代理，或者在应用自身的网络设置里指好代理。
- 应用装在非常规位置且既不在运行、又不属于商店包时，`[2] 体检` 会显示「未找到」，
  用 `[9] 设置` 填一次 `app` 目录（含 `resources\app.asar` 的那一层）即可，设置会记进 `.wakecat-i18n.json`。

**三个小提示**

- 脚本请放在**本地磁盘**运行，PowerShell 5.1 对 UNC（网络共享）路径支持不佳
- 从下载的 ZIP 解开后，`.cmd` / `.ps1` 的文件名带中文没问题：启动器 `.cmd` 内部是**纯 ASCII**，
  用 `%~dp0` 通配自己找同目录的 `.ps1`，主脚本改名也不会失联
- 语言代码以**目标机器上的应用**为准，`[2]` 会打印语言总数，`[3]` 可列出全部代码

## 常见问题

**Q：设置了 `zh-CN`，界面还是英文？**
A：先做两件事 —— ①按 `7` 看开关是否真的能取到；②**完全退出应用再启动**（托盘图标右键 → 退出；只点窗口关闭按钮进程还在，配置不会重载）。

**Q：为什么我的**菜单栏**是中文，界面却是英文？**
A：这是最典型的"只满足了一半条件"。菜单跟随**系统语言**，界面文字才看 `enable_i18n`。
所以「菜单中文」不代表汉化生效，别被它误导。按 `7` 修条件二。

**Q：设置里能选中文，选了却没反应？**
A：语言选项所在的那段代码默认值恰好是 `true`，而真正加载语言包的那段默认值是 `false`。
两处不一致 → 选项显示得出来、点了不生效。根因仍是条件二没拿到。

**Q：汉化要下载语言包、要挂 VPN 吗？**
A：语言包**不用**下载 —— 64 种语言两套资源都随应用安装包落在本机。
界面语言受远程开关 `enable_i18n` 控制，三种方式拿到它：让应用访问一次 `ab.chatgpt.com`（挂代理/TUN）、
走系统代理，或 **v2.1.0 直接 `[7]→2 离线开关注入`，全程不用联网**。

**Q：那我在能用的机器上把开关导出来、拷到新电脑，行不行？**
A：**盲搬缓存不行**（v1.2.0 试过，3 台机器全部失败）—— 搬过去的键绑的是来源机器的 `stableID` / 登录身份，
在新机器上键对不上、值也会被判无效。**但现在可以"现场算键再注入"**：v2.1.0 的 `[7]→2 离线开关注入`
会读目标机器自己的 `stableID`、现场算出正确的键再写入，**换机器、离线都没问题**。别用旧办法搬键，用新办法注入。

**Q：为什么别的电脑上跑了脚本，界面还是英文？**
A：那台机器没能让应用取到条件二的开关。按 `7`，它会直接告诉你卡在哪一步、下一步做什么。

**Q：`[7]` 的"保存诊断报告"里有什么？会不会泄露账号？**
A：只有应用版本/路径、`localeOverride`、系统代理设置、几个域名的直连探测结果、开关实测结果。
**不含任何账号、令牌或密钥**，可以直接发出来排障。

**Q：会不会影响应用签名 / 被打上篡改标记？**
A：不会。`WindowsApps` 目录一个字节都没动，不存在 asar 完整性熔丝（integrity fuse）问题。

**Q：这个版本会不会已经不提供简体中文了？**
A：`[2] 体检` 若显示「简体中文资源：缺失」，就说明确实没有。此时本工具**不会**硬塞一份残缺翻译进去 ——
那正是第三方包的老毛病。

**Q：想换别的语言？**
A：`[3] 切换界面语言`，64 种任选（日语、韩语、德语……）。

**Q：`config.toml` 被我改坏了怎么办？**
A：每次改动前都会自动备份到 `backups\`（保留最近 5 份），把 `.bak` 改回原名覆盖即可。

## 已知限制

- **开关的"默认值"层面已无死角**：三种方式（联网拉取 / 系统代理 / **v2.1.0 离线注入**）都能让应用拿到 `enable_i18n = true`，
  任选其一即可；离线注入链路在国内离线环境尤其有用。
- **盲搬缓存不可行**：把别台机器算好的键照搬过来必然失配（键绑来源机器 `stableID`）。正确做法是 v2.1.0 的**现场算键再注入**。
- **离线注入依赖 LevelDB 缓存格式**：应用若大幅改动其本地缓存格式（概率低），`[7]→2` 会检测异常并中止，不会写入。
- **覆盖层文案不保证生效**：见上文「关于那两条覆盖层文案」，那是应用自身的未翻译项。
- **仅支持 Windows**：脚本是 PowerShell 5.1，依赖 `.cmd` 入口与 Windows 用户目录结构。
- **界面语言 ≠ 功能可用**：能否登录、对话是否流畅由网络决定，与本工具无关。
- **不做版本白名单**：只要应用还带 `native-menu-locales`，就能汉化；应用哪天移除中文资源，体检会如实报「缺失」。

**不需要卸载程序**，因为它没装任何东西。要还原：
